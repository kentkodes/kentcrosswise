## Two modules

The server **public projection module** owns redaction, identity mapping, consistent state, event ordering and delivery/recovery metadata behind a versioned read interface. Its database adapter reads only explicitly permitted sanitized projection data as `web_public`.

The browser **playback module** owns validation, deduplication, separate received/played/current-state positions, bounded transition queues and reconciliation. The room consumes its safe state and animation commands; it does not infer assignments from prose or duplicate transport logic. A fictional adapter exercises the same interface locally.

## Versioned read interface

Proposed route: `GET /api/public/office`. Preserve `/api/public/agent-events` and its five-field response unchanged for the homepage and existing office. Serve the new route with `Cache-Control: no-store` until an independently reviewed bounded-cache/revocation policy replaces it; do not inherit the old route's public caching implicitly. The owner approved that bounded policy on 2026-10-26 (release review P2-1): available bootstrap/state responses may be shared for 2 s; incremental cursors stay no-store.

| Field | Meaning |
|---|---|
| `version` | Closed protocol version; unsupported versions fail visibly without inventing a scene. |
| `available` | Whether this response contains a successful projection observation. Failure is not an empty authoritative snapshot. |
| `observed_at`, `revision` | Server observation time and committed projection revision, represented as a bounded canonical decimal string. Neither is a worker heartbeat or raw source identity. |
| `snapshot` | Safe tasks, role/assignment/execution state, allowlisted waiting reasons, related-task descriptions and explicit pause state. |
| `events` | Opaque event reference, original recorded time, safe role/type, public description or Private task, nullable task/execution references and projection order. |
| `history` | Delivery cursor, consistent watermark, `has_more`, completeness, replay range and explicit gap/recovery metadata. |
| `capabilities` | Which execution, deployment and routing facts are genuinely available. A missing capability cannot trigger invented motion. |

Entity references are randomly assigned opaque public values. The local interface uses prefixed UUIDv4-shaped task, execution, event and generation references; projection revisions and privacy epochs use bounded canonical decimal strings, while cursor tokens are bounded opaque base64url values. Entity references appear only as application data for grouping/deduplication, not as rendered labels or links. They are not secret credentials and must not contain raw task IDs, GitHub run IDs, process/host identities, branches, private text or hashes derived from descriptions. Source event IDs may be retained server-side for deduplication, not reused as delivery watermarks. Shape validation cannot prove random generation, cryptographic cursor binding or trustworthy server provenance.

An assignment-scoped execution reference ends with that execution; retries/replacements receive new references. A stable task reference preserves task continuity across attempts. Persist seat assignment for the same execution; release/reassign only on authoritative evidence. Do not unnecessarily link a worker across unrelated tasks. Parent relations use explicit allowlisted kinds and do not merge parent/child states.

`null` means unavailable or deliberately withheld, not idle, terminal or absent. Use explicit state and reason fields to establish those facts. Validate every field and bound strings/counts; unexpected/raw/private fields fail closed. Private descriptions, summaries and related-work labels all use the generic description, including private Docs children.

## Consistency, ordering and privacy changes

Proposed implementation: a database projection state plus append-only journal and a transaction-held revision-counter lock. Acquire that lock before allocating a public revision and before projection-changing writes; commit journal entries and projection state atomically. Every relevant writer must participate, including task changes, event insertion, execution observations, pause and privacy/deletion changes. Sequence allocation by itself does not establish commit order. Each journal event has a unique total position `(revision, ordinal)`; multiple events within one committed transition receive distinct ordinals.

For example, source event 102 can commit before event 101. A client that reads 102 and then requests `id > 102` can miss the later commit of 101. A projection revision allocated under a transaction-held lock avoids using that source identity as the delivery order. Deduplication prevents duplicate projection when source deliveries repeat.

Return snapshot, event page and watermark from one SQL statement or an explicitly repeatable-read transaction. The current database adapter's `BEGIN READ ONLY` alone is not a promise that multiple queries share one snapshot. Refactor source transitions that must be atomic rather than claiming separate task/event writes are already atomic. External GitHub effects remain separately confirmed outcomes.

An incremental response may contain a snapshot at watermark R and only the first page of events through R. Its opaque delivery cursor encodes or references the exact `(revision, ordinal)` position, projection generation and privacy epoch; bind each catch-up sequence to an explicit watermark and reject incompatible tokens. Advance only through events actually accepted by the client, including when a page ends between events from one revision; do not jump to the snapshot revision. `has_more` is relative to that read's watermark. Bootstrap supplies the current snapshot and a separate latest-20 historical replay window; historical completeness must be explicit.

Use restricted sanitized views/projection functions; do not grant the public reader raw task, checkpoint, owner-text, event-detail or report access. Projection functions, grants and trusted lifecycle reporting require the existing security-critical review before implementation/rollout. Use an append-only migration; do not rewrite applied migrations.

For a public→private change, redact descriptions in place in journal delivery, snapshots, browser logs, pending animations and replay. Preserve task identity, event positions, motion and ordering; the privacy change is not permission to evict queued transitions. Continue connected private work with generic descriptions under the accepted policy. Actual deletion uses an explicit content-free tombstone/invalidation with recovery semantics rather than silently removing accepted history or inventing completion.

Use a monotonic privacy epoch across snapshot polls, event pages, replay and caches. Process invalidation before other content, even while the event queue is full and event fetching has stopped. Reject any older in-flight response once a newer epoch is accepted; an old page must never repopulate a withdrawn description. Epoch changes invalidate or rebind cursor tokens through an explicit recovery response. Server queries must redact old journal payloads using current policy, not only redact the latest snapshot. Prevent subsequent origin delivery of withdrawn content; active clients apply revocation when observed on their next state refresh. Do not claim immediate recall from an offline visitor or erase information already delivered to them.

## State truth and freshness

Proposed technical defaults: poll current state every five seconds and mark its server observation stale at 30 seconds old. This threshold is newly proposed here; it was not part of the owner's earlier sequential-playback answer. Validate server observation time and revision monotonicity, account conservatively for response age/transit, and use monotonic elapsed time after acceptance; future/invalid timestamps cannot establish freshness. A repeated or delayed cached response must not reset freshness just because it arrived successfully. The new route does not inherit the old feed's caching; its bounded 2 s bootstrap/state cache keeps `observed_at` from the cached read, so a cached copy cannot appear fresher than it is. A failed refresh retains last-known data with unavailable/stale messaging, even before that threshold. Empty incremental events do not mark the room idle, done or offline.

Keep runtime observation separate: report its actual source, observation time and phase. A fresh database read never refreshes a worker's liveness. Without verified execution facts, show Starting, reported activity or last-confirmed state with execution unknown; do not animate a model as currently running merely because a start job emitted coding.

Trusted workflow/job observations establish actual work-job starts, cancellation, terminal outcomes and replacement attempts. Keep privileged reporting outside credential-isolated work. Add no telemetry credentials or privileged write capability to untrusted work. Late reports from an older attempt cannot revive it or overwrite its replacement; preserve their historical/usage records without changing the active assignment.

Multiple QA executions keep distinct identities and inspection entries. Reserve/serialize use of the visible QA station for illustrations, with a truthful count and accessible inspection of other executions. Station identity is not worker identity. Additional inspection entries use role/seat/execution context without exposing task IDs or changing the accepted room composition.

## Sequential playback and recovery

Maintain three independent positions: last event accepted for delivery, last transition illustrated, and latest current-state revision. Logs/details distinguish illustrated event/time and pending count from latest confirmed state. A current snapshot cannot silently complete an older animation or discard received transitions.

Proposed limits: 256 pending transitions, pages of at most 50. Request a page only when its maximum size fits in remaining capacity. Advance the received cursor only after validating and accepting the whole page. At capacity, stop event catch-up fetching while continuing separate current-state polling. Deduplicate before queue insertion, retain per-task/per-worker order and reserve shared visual resources so unrelated packets do not teleport or cancel one another. Slow frames lengthen playback; they do not skip pixels or events.

Live, Replay and Fictional sample are whole-scene modes. Retain latest-20 Replay with original timestamps and explicit partial history. Never use a modern snapshot to invent a historical beginning. New live arrivals switch to reconciled live mode under the existing live-priority rule while retaining the interrupted replay position and accepted transitions. Current-state truth and illustrated position remain distinct in every mode.

Retention proposal for the first implementation: preserve the existing no-automatic-deletion behavior; add no pruning job or new expiry policy in this step. Report the actual oldest retained cursor and completeness rather than promising indefinite history. Maintenance, later retention changes, reload or storage limits may make a cursor unrecoverable. That is an explicit gap, not silent success.

On a gap, preserve all recoverable received transitions and clearly show the missing range. Offer an explicit restart/reconcile-to-current action before discarding an unrecoverable remainder. Recovery is a whole-scene transition, never an invented run of missing events. A browser reload must explicitly report the restored/partial history condition; do not claim animation continuity that was not persisted. Durable browser-resume requirements and any future retention limit need separate documented scope before production integration.

## Local validation unit

The first local unit is implemented in [office-contract.ts](../../apps/web/src/office-contract.ts), with [fictional envelopes](../../apps/web/test/fixtures/office-contract.ts) and [focused tests](../../apps/web/test/office-contract.test.ts). `parseOfficeEnvelope(unknown)` returns an independent typed copy or a bounded reason code. It rejects unexpected nested fields, malformed references/timestamps/positions, oversized collections, private description leaks and contradictory task/execution associations. The unavailable branch carries no private diagnostic text. Core role/event allowlists and printable-ASCII public-title hygiene match current source; the validator does not replace server sanitization.

The concrete interface keeps nullable task/execution inventories, separate execution phase/trusted observation/reported activity, task kind independent of the current review role, explicit relation labels, revision/ordinal positions and bound history metadata. Entity-reference shape, not random allocation, is checked. Opaque cursor shape and envelope consistency, not cryptographic binding, are checked. Cross-response epoch rejection, freshness/liveness decisions, durable persistence and playback behavior remain later modules.

Current limits: 256 task/execution/relation/invalidation entries per corresponding inventory, 50 delivered events, 20 replay events, 60 printable-ASCII description characters, 512 cursor characters, 20-digit canonical counters and ordinal maximum 65,535. These are protocol validation limits, not worker concurrency or retention policies. Client queue capacity 256 and the five-second/30-second freshness proposal are not implemented by this parser.

The fictional cases include two distinct private histories, public work, related Docs work, unknown execution and successful terminal execution. Independent review resolved null-inventory redaction/related-label and reused-execution association defects before final validation. The 16 focused tests pass.

Invalidation kinds: `redact` means earlier labels are withdrawn and the task is private now; only "Private task" may appear for it, with or without a task inventory. `relabel` means an earlier public label is withdrawn and the task is public now; the task's current row must be in the inventory and is the only label allowed for it. A `relabel` without an inventory is rejected. `delete` is the content-free tombstone. Clients purge every earlier label of an invalidated task and adopt the current row. No network/database calls, production imports, new dependencies, public route changes or room changes are included.

## Local projection unit

Unit 2 lives in [0006_office_projection.sql](../../packages/db/migrations/0006_office_projection.sql) and the [read adapter](../../apps/web/src/server/office-projection.ts), with [database tests](../../packages/db/test/office-projection.test.ts) and [adapter tests](../../apps/web/test/office-projection.test.ts) plus review regressions ([1](../../apps/web/test/office-projection-qa.test.ts), [2](../../apps/web/test/office-projection-qa2.test.ts)). The local /api/public/office route uses this adapter; local Unit 3 writers enqueue projection work through the outbox.

- **Storage.** A single projection-state row (generation, revision, privacy epoch, pause, capabilities that only turn on), random UUIDv4 references mapped to source keys server-side, projected task and execution state, an append-only journal keyed by `(revision, ordinal)` without descriptions, source-delivery dedupe and a privacy-change log.
- **Writer.** `office_project(source_key, transition)` runs in the caller's transaction. It takes the state-row lock, then checks dedupe, then allocates one revision; events of one transition get ordinals 0, 1, … . It is `SECURITY DEFINER` with EXECUTE granted to no application role. The accepted unit-3 design keeps it internal: source triggers enqueue atomically and a separate `office_drain` function, executable only by `orch_rw` and `web_rw`, invokes the writer. Source writers never take the projection lock. See [UNIT3-PLAN.md](UNIT3-PLAN.md) for the locally implemented design.
- **Dedupe.** Each delivery stores the core `sha256` digest of the canonical transition. The same key with the same content is a no-op (NULL). The same key with different content raises SQLSTATE `P0K01` with a fixed message; writers treat it as a bug, not a retry.
- **Validation.** Unknown keys and the unit-1 association rules are rejected. Timestamps must be ISO-8601 with a zone, finite, not before 2000-01-01Z and not in the future; table checks enforce the bounds and the event view skips any implausible row. A terminal execution cannot change phase or outcome, and parent links cannot form a cycle. Titles failing printable-ASCII 1–60 become "Private task". Error text names the rule, never input values.
- **Public surface.** web_public reads only five sanitized `v_office_*` views; raw tables, mapping/source keys and the writer stay denied. `v_public_agent_events` and the five-field feed are unchanged.
- **Reads.** Snapshot, event page, replay window and watermark come from one SQL statement. Modes are `bootstrap` (snapshot plus the latest-20 replay, complete only when it reaches the generation's first journal entry; pre-0006 events are not backfilled), `incremental` (pages of at most 50 after an opaque cursor binding generation, privacy epoch, position and issuing watermark) and `state` (snapshot only; optional client `privacy_epoch`). Malformed cursors, epochs and page sizes are request errors; another generation or a cursor beyond the current watermark gets a restart gap.
- **Privacy changes.** A public→private change or a public retitle withdraws the old label and bumps the epoch once per transition. Descriptions are read from current task state, so earlier journal entries are redacted in place. A client at an older epoch (incremental or state) gets a `privacy_changed` gap with every withdrawal since its epoch, plus each invalidated task's current row. The kind follows current visibility (`redact` if private now, `relabel` if public now, also after a redact and a later republish). The client rebinds by repeating the request with `rebind: true` and continues from the same position under the new epoch. More than 256 pending invalidations, or a task inventory beyond its limit, gets a `privacy_changed` restart instead.

Unit 3 is implemented and independently validated locally: per-row versions, handled outbox rows without a high-water mark, a single ordered best-effort drain, signed workflow observations and console pause wiring. Owner accepted requested runs as `starting` from `trusted_workflow`, the three task `run-name` workflow additions and immediate `P0K01` dead marking / eight-failure retry cutoff. Execution observations are enabled only in local validation after tests; deployed/router stay off. No historical backfill. Unit 4 implements cross-response freshness, epoch reconciliation and bounded playback locally; Unit 5 adds the local connected-room adapter. Critical review remains required before rollout; no live operation is authorized by this document. Current source/release status remains in [HANDOFF.md](../HANDOFF.md); pending work is tracked in [OPEN-POINTS.md](../OPEN-POINTS.md).

## Local playback unit

[office-playback.ts](../../apps/web/src/office-playback.ts) adds a deterministic controller with no transport, timer, storage or room imports. It validates envelopes before use, keeps current revision separate from accepted delivery and completed illustration, and serializes one active transition. Only explicit completion advances an illustration; pause, elapsed time and polling do not skip transitions. A room adapter must refresh every copied label when the accepted epoch changes.

Pending plus active transitions are capped at 256. An incremental request requires space for a full 50-event page; state requests continue at capacity. A page advances its cursor only after whole-page acceptance. Older delivery pages can remain useful while their snapshots cannot regress current state. Privacy withdrawals update current, pending, active, log and replay content before delivery checks; content-free tombstones preserve event references and positions when labels must be suppressed. A generation change latches an explicit restart gap and rejects further old-generation content.

The five-second poll helper and 30-second stale threshold use caller-supplied wall and monotonic clocks. Response transit counts toward age; cached timestamps cannot reset it, future/invalid clock observations cannot establish freshness, and failed refreshes retain last-known data with unavailable status. Execution observation timestamps remain untouched: database freshness does not establish worker liveness.

Latest-20 replay keeps original timestamps, completeness and interrupted position; explicit rewind resets only replay progress while preserving live history. Live arrivals interrupt replay at a whole-scene boundary; the interrupted replay beat remains available. Fictional mode is an explicit inactive boundary for the later adapter, not a source of invented live events. Gap recovery is explicit; restart invalidates outstanding requests and reports partial history. No durable browser resume or automatic log pruning is implemented. Unit 5 adds local network/timer wiring and rendering; actual deployed transport, physical devices and durable resume remain later verification.

Focused implementation and independent QA tests are [office-playback.test.ts](../../apps/web/test/office-playback.test.ts) and [office-playback-qa.test.ts](../../apps/web/test/office-playback-qa.test.ts). Current verification totals and limitations are recorded in [HANDOFF.md](../HANDOFF.md).

## Local connected-room unit

The sibling [connected page](../../apps/web/src/app/%28public%29/office/connected/page.tsx) connects the controller to the accepted room through [office-room.ts](../../apps/web/src/office-room.ts). The [shared renderer](../../apps/web/src/app/%28public%29/office/draft/draw-office.ts) accepts a neutral render model; its default fictional adapter preserves the original draft. Real task/execution references never map onto fictional task keys. Geometry caches references and positions, while labels come from the current controller view. Tombstones purge saved live geometry and neutralize active withdrawn transitions.

The client has independent state and delivery lanes, each polled every five seconds (`OFFICE_PLAYBACK.pollMs`) only while the document is visible; a hidden tab starts no office requests, and becoming visible again fetches state and events once before the intervals resume. It uses no-store fetches, ten-second request deadlines, unmount cancellation, continued visible state polling during playback pause/backpressure, and explicit history recovery. Actual assignments determine drawn seats; unassigned executions remain inspectable. Every QA/overflow execution has a separate inspection entry. Current execution/task/pause evidence is separate from illustrated events and replay; role-only Developer events make no seat claim. Replay retains its partial baseline and original timestamps, with saved live geometry restored as a whole scene when live work takes priority. Only completed merge transitions file packets; Docs and deployment remain independent.

[GET /api/public/office](../../apps/web/src/app/api/public/office/route.ts) strictly allows bootstrap, state and incremental query fields. Available bootstrap/state responses send `public, max-age=2, s-maxage=2` (CloudFront keys on the full query string, so a privacy withdrawal can appear up to 2 s later); incremental, unavailable and error responses are no-store. The public read runs with a transaction-local 3 s statement timeout. Unknown, duplicate, incompatible or malformed fields fail before the loader reads a database. The old five-field route is unchanged. The new route and migration/grant changes remain local and unpublished; earlier browser verification intercepts successful API responses with synthetic protocol envelopes. A later local integration check uses a populated synthetic database and actual public-role route responses to verify replay timestamps, task filtering, paused privacy withdrawal/rebind, live arrivals and terminal state; its fixture does not establish assigned-worker event motion or deployed transport.
